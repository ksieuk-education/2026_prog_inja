## C4‑модель: сервис заказа поездок

Небольшой учебный пример архитектуры сервиса наподобие такси‑приложения.

### Предметная область и API

- **Сущности**: пользователь, водитель, поездка.
- **Основные операции API**:
  - создание пользователя и поиск по логину / имени и фамилии;
  - регистрация водителя;
  - создание заказа поездки;
  - получение активных заказов и принятие заказа водителем;
  - история поездок пользователя;
  - завершение поездки.

### Роли и внешние системы

- **Роли**:
  - пассажир;
  - водитель;
  - администратор.
- **Внешние системы**:
  - платежная система;
  - SMS‑сервис;
  - email‑сервис.

### Что описано в `workspace.dsl`

- **System Context (C1)** – один software system «Сервис заказа поездок» в окружении трёх ролей и трёх внешних систем.
- **Container (C2)** – контейнеры внутри системы:
  - мобильные приложения пассажира и водителя;
  - веб‑приложение администратора;
  - API Gateway;
  - сервисы пользователей, водителей и поездок;
  - сервис уведомлений;
  - сервис платежей;
  - база данных (PostgreSQL).
- Для контейнеров и связей указаны технологии и протоколы (например, `Spring Boot`, `REST API`, `PostgreSQL`, `HTTPS/REST`, `JDBC`).

### Dynamic‑диаграмма

Dynamic‑view показывает сценарий **создания заказа поездки**:

- пассажир из мобильного приложения создаёт заказ;
- запрос проходит через API Gateway в `Trip Service`;
- проверяется пользователь, авторизуется платеж, поездка сохраняется в БД;
- рассылаются уведомления и ответ возвращается клиенту.
